⚖️ Evals System — Complete Guide

How the AI evaluates itself, when humans step in, and how to run & interpret benchmarks.

1. Quality Gate Pipeline

Every response the AI generates passes through the Quality Gate — a loop that generates, judges, and retries if the quality is below threshold. This prevents bad responses from reaching users.

2. LLM-as-a-Judge

The judge is a separate LLM call (default: llama-3.1-8b-instant at temperature 0.1) that evaluates responses on two axes. It receives the system prompt, humor anchors, and expected language, then returns a JSON verdict.

Axis Range Threshold What it measures
language_purity 0 – 10 ≥ 8 Correct language? No mixed scripts? Grammar & register appropriate?
quality 0 – 10 ≥ 6 Humor mechanism used? Fits personality tone? Avoids being robotic/cringe?
// Judge JSON output format
{ "scores": { "language_purity": 8, "quality": 7 }, "feedback": "Good personality but slight language mix", "main_issue": "language" }

3. Rule-based Fast-path

Before calling the LLM judge, a regex-based script detector scans the response. If it finds characters from a non-expected script (e.g. Korean hangul in a Spanish response), the response is automatically failed with language_purity = 0 — no LLM call needed. This saves tokens and catches obvious language mixing instantly.

Detected Script Unicode Range Language

4. Transcreation (Cultural Adaptation)

For non-Latin scripts, the generator first produces a response in the source language (Spanish or English), then transcreationService.js adapts it culturally to the target language. This preserves humor mechanisms while localizing references.

ko (Korean) th (Thai) ar (Arabic) ja (Japanese) ru (Russian) zh (Chinese) vi (Vietnamese) hi (Hindi)

If transcreation fails after 2 retries, the original Spanish/English response is used as fallback (marked with ⚠️ FB in the evals table).

5. Benchmarks

A benchmark runs the entire golden dataset through the Quality Gate and records pass rates, scores, and regressions. Results are stored in the EvalRun collection and displayed in the 📊 Benchmarks tab.

📁 Dataset files
tests/evals/test_queries.json — main personality + edge case tests
tests/evals/golden_datasets/ — intent, personality, language, transcreation, edge datasets
tests/evals/golden_datasets/local_overrides.json — promoted from HITL

The regression detection automatically compares the latest run against the previous one. If pass rate drops by 5% or more, a 🔴 regression banner appears. You can also compare two specific runs side-by-side.

Datasets: all, intent, personality, language, transcreation, edge, summary
Models: llama-3.3-70b-versatile, Qwen2.5-7B-Instruct

6. Human-in-the-Loop (HITL)

The HITL system captures responses that need human review. A human can verify the judge's decision, correct it, and optionally promote good examples to the golden dataset.

Source When it triggers Priority
force_approved Quality Gate exhausted 3 retries Highest
user_downvote User gave a rating of 1-2 ⭐ in the chat High
judge_disagree Human disagrees with the judge's verdict Normal

In the 👁️ Human Review tab you can see pending reviews, submit verdicts (pass/fail with confidence level), and promote good responses to the golden dataset. The stats card shows agreement rate, false positives (judge said pass, human said fail) and false negatives (judge said fail, human said pass).
